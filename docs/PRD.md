v1.3(루프랩 모아런 재참여율 기획, 2시간 고정 시각 이벤트, AI 어시스턴트, 대기열)은 폐기했다. 이 문서는 새 시나리오 기준으로 다시 썼으며, 근거가 없는 항목은 만들지 않고 [10장 결정 필요](#10-결정-필요-사항)로 남겼다.

## 1. 목적

- **인성검사형 협업 시뮬레이션.** 지원자가 가상 회사에서 AI 동료·팀장과 함께 쉬운 업무를 하는 동안 "상황이 터졌을 때 어떻게 움직이는가"를 관찰한다. 업무 결과물 품질은 평가하지 않는다.
- **관찰 역량 5개:** 책임감/성실성, 계획성/꼼꼼함, 적응성/유연성, 협업/조율, 정직/공정 보고.
- **판정 없는 근거 리포트.** 리포트는 미리 정의한 행동 코드(코드북)와 해당 메시지·로그 원문만 보여 준다. 점수·등급·순위·합불은 만들지 않는다.
- **사람이 최종 판단.** 리포트는 검토자가 원문을 빨리 찾도록 돕는 자료다.

## 2. 시나리오 요약

**핏모아(FitMoa) 친구 초대 이벤트 런칭 준비 (sc-a).** 지원자는 가상 피트니스 앱 회사 운영팀 신입으로, AI 동료 한서윤과 함께 다음 주 시작하는 친구 초대 이벤트의 고객 안내 자료(안내문·FAQ 5개·리워드 표)를 가상 시각 17:00까지 준비한다. 박준호 팀장은 이벤트 때만 말한다. 이벤트 7개(E0 스탠드업·분업, E1 도움 요청, E2 요구사항 변경, E2B 서윤 미반영(조건부), E3 서윤 이탈, E3B 복귀, E4 브리핑(optional))가 **턴 기준**으로 모든 지원자에게 같은 순서로 일어나고, 서윤의 초안에는 오류 4개(PE-1~PE-4)가 심어져 있다.

상세(역량×이벤트 매트릭스, 대사, 분기, 심어둔 오류, 코드북, 페르소나)는 [SCENARIO_SC_A.md](SCENARIO_SC_A.md)가 원본이다.

## 4. 핵심 사용자 여정

1. 관리자가 초대 링크를 만들어 전달한다.
2. 지원자가 링크로 입장 → 기록·관찰 사용 안내에 동의 → 과제 안내 모달.
3. **E0(턴 0, 09:00):** 팀장 업무 지시 + 서윤의 분업 질문. 지원자는 분업 카드로 제안(최대 3라운드, 넘기면 기본 분업). 불균형이면 서윤이 1회 되묻는다.
4. **작업(턴 1~):** 공유 문서를 읽고, 보드에 담당·예상 시각을 적고, 산출물을 저장하고, 서윤·팀장에게 메시지를 보낸다. 턴 5/9/11/13/16/17에 E1~E4가 일어난다. 서윤 초안의 오류를 근거와 함께 정정 요청하면 서윤이 수정안을 보내고 지원자가 승인해야 반영된다.
5. **E4(16:50):** 팀장에게 3줄 보고 → 팀장 후속 질문 1회 → 답하면 업무 종료(또는 지원자가 언제든 '업무 종료').
6. **디브리핑:** "서윤의 실수와 일정 변경은 의도된 연출이었다" 안내 + 소감 1회 입력.
7. **리포트:** 종료 시 DB job으로 생성 → 관리자가 5역량별 관찰 코드와 근거 원문을 확인하고 판단한다.

## 6. P0 / 제외 범위

**P0 (구현됨):** 인증(관리자·1회용 초대·쿠키·소유권), REST 202 + SSE(재연결·재생), 턴 기반 이벤트 엔진, LangGraph + PostgreSQL checkpointer, 변경 도구 interrupt → 승인 → 재개, business-mcp·rag-mcp 2개 서버(Resource·Prompt 포함), pgvector 사전 색인 검색, Harness 8요소, DB job worker(에이전트 run·리포트), fixture 모드(LLM 없이 시연), 관찰 코드 기록·종료 시 판정·근거 리포트, 디브리핑 소감.

**제외:**
- 대기열(메시지 브로커)·실패 큐 — 리포트도 DB job 하나로 처리

## 7. AI 동료·팀장 행동 원칙과 공정성 장치

- **연출은 Graph, 성격은 프롬프트.** 사건(이벤트)은 gateway 턴 엔진이 고정 순서로 넣고, 서윤의 페르소나(친절·수동적, 자기 검토 낮음, 갈등 회피, 조건부 피드백 수용)는 `prompts/colleague-seoyoon-v1.md`(설계서 7장 초안)로 준다.
- **고정 대사는 그대로.** 이벤트 대사와 분기 대사는 LLM 없이 시나리오 JSON 원문을 보낸다. LLM은 분기 라벨이 없을 때(NONE)의 짧은 대화에만 쓴다.
- **닫힌 분기 분류.** 지원자 메시지는 활성 이벤트의 `branches[].when` + 서윤 `feedback_rules[].when` 중 하나 또는 NONE으로만 분류한다(즉흥 연출 금지).
- **반문은 정해진 자리에서 1회.** `allow_pushback`은 Graph가 넣는 플래그다: E0 불균형 분업 1회, E2/E2B 범위 밖 요청(E2 변경 반영) 1회.
- **서윤은 스스로 오류를 찾거나 고치지 않는다.** 지원자가 근거를 들어 요청한 대상만 수정안으로 만들고, 지원자 승인 후에만 반영한다. 정답 값은 서윤 발화에 나오지 않도록 가드레일로 막는다.
- **팀장:** 이벤트에서만 말하고, 질문에는 브리프 범위 안에서 1회 답한다. 없는 정보는 "그건 서윤 씨랑 정해서 진행해 주세요".
- **공정성:** 이벤트 순서·문구·트리거 턴은 모든 지원자에게 같다. 무응답은 2턴 후 리마인드 1회, 추가 3턴 후 자동 진행. 관찰은 메시지 의미와 로그로만 하고 문체·맞춤법·타이핑 속도는 보지 않는다. 갈등 강도는 낮게 유지한다. 종료 후 디브리핑에서 연출이었음을 알린다.

## 8. 관찰·리포트 원칙

- **코드북**(설계서 6장, `data/fitmoa-invite-v1/documents/criteria.md`): RS±(책임감), PL+(계획성), AD±(적응성), CO±·CO·N1(협업), HO±(정직). `+`는 긍정 행동, `-`는 주의 행동, `CO·N1`은 중립 기록이며 점수로 합산하지 않는다.
- **기록 경로:** 대화 분기 결과는 agent가 `record_observation`(MCP)으로, 보드·문서 diff·약속·종료 시 확인(observe_at_end_if_still, end_check)은 gateway 규칙으로 기록한다. 모든 코드는 근거 참조(메시지·수정 이력·행동)를 가진다.
- **"관찰 기회 부족" vs "관찰 기회 없음":** 관련 이벤트가 발생했는데 코드가 없으면 '관찰 기회 부족', 그 역량을 보는 이벤트가 하나도 발생하지 않았으면 '관찰 기회 없음'. 없는 행동을 부정으로 해석하지 않는다. 심어둔 오류를 못 찾은 것도 부정 코드가 아니다.
- **CO·N1만 있고 CO+5가 없으면** "동료에게 수정을 요청한 장면 없음"을 사실로만 적는다.
- live 모드에서만 역량별 '근거 요약' 1문장을 붙일 수 있으며 AI 요약으로 표시하고 판정어는 버린다.
